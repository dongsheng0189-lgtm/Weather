# Dependency Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace loose `>=` deps with a pip-tools lockfile (pinned + hashed), switch torch to CPU-only to drop `nvidia-cuda-*` (~2GB), and add a CI drift-gate — rooting out the F17 incident #13 dependency-drift class.

**Architecture:** `requirements.in` (human-edited direct deps) → `pip-compile --generate-hashes` → `requirements.txt` (fully pinned + hashed lockfile, same filename so Dockerfile.base needs no path change). `face_recognition`/dlib/face_recognition_models stay out of the lock (provided via `wheels/` + a `--no-deps` install). A new `deps-lock.yml` workflow fails CI if `requirements.txt` is out of sync with `requirements.in`. One base-image rebuild rolls it out.

**Tech Stack:** pip-tools 7.5.3, PyTorch CPU index, Docker (Dockerfile.base), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-06-12-dependency-hardening-design.md`

**Branch:** `chore/dependency-hardening` (already created; spec committed at `577b989`)

**Pre-resolved facts (probed 2026-06-12):**
- `torch==2.12.0+cpu` exists on `https://download.pytorch.org/whl/cpu` (matches current GPU torch-2.12.0 — same version, CPU variant, no version bump).
- `pip-tools==7.5.3` is current latest.
- venv = Python 3.12.3 / x86_64, matches prod base `python:3.12-slim`.

- [ ] **Step 3: Create the wrapper script**

Create `app_unified/scripts/lock-deps.sh`:
```bash
#!/usr/bin/env bash
# Re-lock app_unified deps: requirements.in -> requirements.txt (pinned + hashed).
#
#   bash app_unified/scripts/lock-deps.sh            # re-lock, NO version bumps
#   bash app_unified/scripts/lock-deps.sh --upgrade  # bump to latest allowed by .in
#
# Run from repo root. Uses the project venv (Python 3.12, matches prod base).
# CI (.github/workflows/deps-lock.yml) re-runs the no-upgrade form and fails if
# the committed requirements.txt differs — so always commit the regenerated file.
set -euo pipefail

PIP_TOOLS_VERSION="7.5.3"
PIP="./venv/bin/pip"
PIP_COMPILE="./venv/bin/pip-compile"

# Ensure the exact pip-tools version (keeps local output identical to CI).
if ! "$PIP_COMPILE" --version 2>/dev/null | grep -q "$PIP_TOOLS_VERSION"; then
  "$PIP" install "pip-tools==${PIP_TOOLS_VERSION}"
fi

UPGRADE_FLAG=""
if [ "${1:-}" = "--upgrade" ]; then
  UPGRADE_FLAG="--upgrade"
fi

"$PIP_COMPILE" \
  --generate-hashes \
  --allow-unsafe \
  $UPGRADE_FLAG \
  --output-file app_unified/requirements.txt \
  app_unified/requirements.in

echo "OK: app_unified/requirements.txt regenerated. Review the diff and commit it."
```

Note on `--allow-unsafe`: pins `setuptools` (already a direct dep here) deterministically; without it pip-compile leaves setuptools unpinned, which `--require-hashes` rejects.

Run:

Expected: no output.

## Task 6: Add deps-lock.yml drift-gate workflow

**Files:**
- Create: `.github/workflows/deps-lock.yml`

- [ ] **Step 1: Create the workflow**

Create `.github/workflows/deps-lock.yml`:
```yaml
name: Deps lock drift-gate

on:
  pull_request:
    paths:
      - 'app_unified/requirements.in'
      - 'app_unified/requirements.txt'
      - '.github/workflows/deps-lock.yml'
  push:
    branches:
      - main
    paths:
      - 'app_unified/requirements.in'
      - 'app_unified/requirements.txt'
      - '.github/workflows/deps-lock.yml'
  workflow_dispatch:

jobs:
  lock-check:
    runs-on: ubuntu-latest
    container: python:3.12-slim
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Install pinned pip-tools
        run: pip install --no-cache-dir 'pip-tools==7.5.3'

      - name: Recompile (no upgrade — reuse committed pins)
        run: |
          pip-compile --generate-hashes --allow-unsafe \
            --output-file app_unified/requirements.txt \
            app_unified/requirements.in

      - name: Fail if lockfile drifted
        run: |
          if ! git diff --exit-code app_unified/requirements.txt; then
            echo "::error::requirements.txt is out of sync with requirements.in."
            echo "Run 'bash app_unified/scripts/lock-deps.sh' locally and commit the result."
            exit 1
          fi
```

Note: without `--upgrade`, pip-compile reuses the existing committed `requirements.txt` pins as constraints, so a newer upstream release does NOT cause a spurious diff — only an un-recompiled `requirements.in` change does.
