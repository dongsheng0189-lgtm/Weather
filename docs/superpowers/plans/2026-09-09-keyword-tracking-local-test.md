## 0. 準備（兩行）

```bash
cd ~/project/webapp/app_unified
bash scripts/run_local.sh          # 另開一個終端機讓它一直跑
```

再開一個終端機，灌入建檔追蹤的測試資料：

```bash
cd ~/project/webapp/app_unified
set -a; source .env.local; set +a
../venv/bin/python scripts/seed_tracking_demo.py
```

> 這支腳本是 idempotent 的，重跑不會產生重複資料。
> 想清掉重來：`../venv/bin/python scripts/seed_tracking_demo.py --reset`

登入：<http://localhost:5000/dev> —— 免密碼，點名字就切換身分。

## 一、基本流程（用 `alice`，北店）

1. 進 `/notes/`，toolbar 應該看得到 **🔎 建檔追蹤**。點進去 → 空清單，顯示引導文字。
2. 回 `/notes/`，展開「⚙️ 進階篩選」，搜尋 `Kevin`。
3. 結果上方出現 **「Kevin」＋ 建檔追蹤按鈕**。按下去。
   - 按鈕應變成 **建立中…**（第一次是全歷史掃描）。
4. 跳到追蹤表 → **應該有 15 列**。標題是「Kevin 建檔追蹤」。
5. 標題附近應該有 **最後更新：MM/DD HH:MM**（會比現在早幾秒，這是對的——它顯示的是資料實際被檢查過的時間）。
6. 列的順序是**新到舊**；日期／來源／原文照舊排列，不再各自帶備註框。

## 二、備註（整張表共用一欄，在頁面最上面）

7. 頁面最上面（標題、「最後更新」下方）應該有**一個**備註輸入框——不是每一列
   各自一個。在裡面打字 → **點別的地方讓它失焦** → 重整頁面 → 文字還在。
8. 備註存好之後，備註框附近應該顯示 **誰在什麼時候改的**。
9. 再改一次同一則備註 → 顯示的人與時間要更新。
10. 把備註**清空** → 重整 → 確實是空的。
    （清空這個動作有被記進 log，舊文字在資料庫裡留著，只是目前沒有畫面可以看。）
11. 貼一段**超過 500 字**的文字 → 輸入框本身就會擋住，不會讓你打進去。

## 三、不相關（整店共用、可復原）

12. 對某一列按 **[不相關]** → 按鈕變成「再按一次確認」→ **不要按第二次**，等 4 秒 → 應該自己變回「不相關」。
13. 這次按兩下 → 該列消失。重整 → 仍然不在。
14. 頁面下方應該有 **「已剔除 (1)」** 的摺疊區 → 展開 → 看得到剛剛那筆，含**誰剔除的、什麼時候**。
15. 按它的**復原** → 該列回到主清單。重整確認。
16. 換 `bob`（同樣北店）登入 → 開同一張追蹤表 → **看到的剔除狀態跟 alice 一樣**（整店共用，不是每人一份）。

## 四、點進原文 ↔ 返回（★ 這段是你上次回報的兩點，這次新修的）

> 你上次說：「進原文後返回會跑到主畫面」「進原文沒有定位到關鍵字」。以下就是驗這兩件事。
> ⚠️ 兩種筆記的畫面**本來就不一樣**，別以為是壞掉：
> 一般筆記用大文字框（游標選取定位），檢查清單才有右下角那個 🔍 命中小工具。

**A. 一般筆記（列的日期後面**沒有** `· 項目` 的那種）**

17. 隨便挑一列，按 **[→ 原文]**。網址應該長這樣（順序不拘）：
    `/n/<筆記id>?q=Kevin&from=/n/tracking/<表id>`。
18. 內文框裡的第一個 `Kevin` 應該**被選取起來**（反白），而且畫面自動捲到那一行——
    不是停在最上面要自己找。（一般筆記沒有 🔍 小工具，這是刻意的。）
19. 這個頁面**必須還能編輯**（標題、內文都點得動、改得了）。
    如果它變成唯讀、或上方出現「🔒 檢視模式」橫幅，那是誤套了 AI 摘要那條 review-mode，要回報。
20. 往下捲一點 → 右下角出現藍色浮動鈕，標籤應該是 **← 返回追蹤表**（不是「← 返回」）。
    按下去 → 回到**剛剛那張追蹤表**，不是筆記列表、不是主畫面。

**B. 檢查清單的項目命中（列上標著 `· 項目` 的那種，來源是「開店/收班檢查清單 A～E」）**

21. 挑一列有 `· 項目` 的，按 [→ 原文] → 網址結尾多一個 `#item-<id>`，
    畫面應該**直接捲到那個項目**，該列黃底、`Kevin` 被 `<mark>` 標黃。
22. 右下角出現 **🔍 n/N 命中** 小工具。按 **▶** 會跳到同一篇的下一個命中
    （只有一個命中就是 1/1，按了原地不動，正常）。
23. 按小工具上的 **← 返回** → 回到那張追蹤表。
    （這顆跟 A 的浮動鈕是同一套行為，不是 `history.back()`。）

**C. 未存檔時返回（這條在驗不會靜默漏存）**

24. 再點一次任一列的 [→ 原文]，**先改一個字**（讓它變成未存檔），再按返回 →
    按鈕應該先顯示 **💾 儲存並返回**、存好才跳回追蹤表。回追蹤表後再點進同一篇 →
    **剛剛那個字要在**。

## 五、增量掃描（這是這個功能的核心）

25. 新增一則含 `Kevin` 的 checklist 項目 → 回追蹤表 → **新項目有出現**，且原本的 15 筆沒有變成 30 筆。
26. 找一個**原本不含** `Kevin` 的既有項目，把它**編輯成**含 `Kevin` → 回追蹤表 → 它出現了。
    （這條在驗水位是用 `updated_at` 而不是「最大 id」——只看 id 的話編輯過的舊資料永遠抓不到。）
27. 把步驟 13 剔除掉的那筆，去把它的**原文編輯一下**（隨便改個字）→ 回追蹤表 → **它不可以復活**。
28. **刪除**一則含 `Kevin` 的筆記 → 回追蹤表 → 該列消失。
29. 到 `/admin/` 把它**還原** → 回追蹤表 → **它要回來**。
    （這條是全分支審查抓到的 Critical：還原時如果沒有更新 `updated_at`，這筆資料就永遠掃不到了。）

## 六、店別隔離

30. 回 `/notes/` 搜尋 `Kevin` → 上方按鈕應該變成 **開啟追蹤表**（不是再建一張）。
31. 換 `carol`（南店）登入 → 搜尋 `Kevin` → 建檔追蹤 → **只有 2 筆**（南店的），看不到北店那 15 筆。
32. `carol` 的 `/notes/tracking/` 清單裡**看不到**北店那張表。

## 七、super_admin 的店別範圍（容易出錯的一段）

33. 用 `admin`（super_admin，北店）登入，**不要**指定店別，搜尋 `Kevin`。
    → 結果橫跨兩店，所以**不該出現建立按鈕**，應該顯示「請先在上方選一間店別」。
34. 點上方店別頁籤切到 **南店**，再搜尋 `Kevin` → 這時才有建立按鈕。按下去。
    → 建出來的表要是**南店**的（2 筆），不是 admin 自己的北店。
35. 在那張南店表上：點得進去、備註存得起來、刪得掉（不會 403）。
36. 還是在那張**南店**表上，按 [→ 原文] → 網址的 `from=` 應該帶著 `?store=南店`；
    看完按返回 → 回得到那張南店表，**不會 403、也不會掉回自己的北店**。
37. 用 `super_admin`（**無店別**）登入 → 進 `/notes/tracking/` → 應該看到明確的「找不到店別」錯誤，
    **不是**一個空清單。（空清單會讓人以為「這店沒東西」，而不是「你沒有店別」。）

## 八、順便驗一下這次一起修的東西

38. 進階篩選面板：**收起來** → 重整 → 應該還是收著的。
    再切一次排序（讓網址帶上 `?sort=created`）→ 重整 → **仍然收著**。
    （這就是你回報的那個 bug：以前只要 URL 上有任何篩選條件，就會強制展開、蓋掉你的選擇。）
